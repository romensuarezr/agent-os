# Idea: Namespacing de config runtime — `config/` → `.agents/config/` (candidata Sprint 12)

**Problema:** `discover-fleet.sh --apply` escribe `config/fleet.yaml` en la raíz del repo donde se ejecute, incluidos proyectos hijos. Muchos hijos ya tienen su propio `config/` (Rails, Laravel, Nest...): nuestro `fleet.yaml` aterriza mezclado con la config de su app y suma clutter a la raíz.

**Propuesta:** un único path canónico `.agents/config/` para core e hijos (toda la familia config/, no solo fleet.yaml — un agente con cero contexto no puede adivinar dos convenciones). `install.sh` debe excluir `.agents/config/` al instalar: hoy la división `.agents/` (instalable) vs `config/` (no instalable) impide que el fleet.yaml del padre fugue al hijo; hay que reponer esa exclusión explícitamente. Actualizar consumidores (fleet-doctor.sh, discover-fleet.sh, import-secrets.sh, generate-homepage-config.sh), skills y reglas que referencien `config/`, docs y checks de validate-control-plane.sh. Re-verificar suite 12/12.

**Origen:** observación del usuario el 2026-09-28 durante la revisión de T-076. No implementar ahora; queda para triaje del Sprint 12.
